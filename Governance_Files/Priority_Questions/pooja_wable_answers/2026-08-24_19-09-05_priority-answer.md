# Priority Question Answer

Question:
How is the extent cache invalidated so users are not shown stale wells after a data refresh or filter change?

Answer:
The cache is keyed only on the bounding box — it's nulled by clearWells() whenever filters are cleared or the map leaves the well band, and filters bypass it entirely (filteredRef short-circuits the zoom watcher, and applying a filter fetches through getMatchedWellsMap, a different endpoint that ignores extent), so a filter change can never serve cached wells.
