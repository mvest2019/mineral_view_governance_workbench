# Priority Question Answer

Question:
Has dev or security approved injecting raw CSS and JavaScript into CMS pages via React useEffect?

Answer:
No such approval exists on record — and the governing rules doc explicitly forbids the pattern: content HTML must be static markup only ("Do not add inline JavaScript," "No inline JavaScript in content HTML," no per-page CSS), with styling coming exclusively from the approved global stylesheet classes (glossary-list, faq-question, etc.) and all interactivity from one dev-owned global FAQ script — the rulebook was written precisely so no page ever injects its own CSS/JS. If any live page currently does useEffect injection, it's an unapproved implementation shortcut carrying real costs: an XSS/CSP surface security hasn't reviewed, hydration/flicker issues, and an SEO penalty we've already observed elsewhere (the /glossary index anchors render client-side only, flagged 2026-08-18 — client-injected content is exactly what crawlers see late or never). Required action: route to dev to replace injection with the sanctioned pattern (global stylesheet + one global script, server-rendered content), and treat any exception as needing explicit dev + security sign-off.
