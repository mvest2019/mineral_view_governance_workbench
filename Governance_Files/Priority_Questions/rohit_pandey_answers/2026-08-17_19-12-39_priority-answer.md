# Priority Question Answer

Question:
Given the common-name collision issue, what verification rule must a name match pass before a dossier tells a user we found their minerals?

Answer:
A match must pass three gates before a dossier surfaces it: (1) token match against the indexed owner roll (search_tokens, order-independent, all tokens present); (2) surname-position alignment — the roll is surname-first, so the roll owner's surname token must equal the prospect's registered last name (this is the fix that correctly rejected Kenneth Dawson), with confidence recomputed only on aligned matches; (3) single unambiguous aligned owner — the recorded-fact enrichment (2025 CAD value, production, value preview) runs only when exactly one aligned owner survives, never on ambiguous sets. And even a passing match is never asserted as ownership: the standing language is "may own / verify" — the dossier presents it as a possible match for the member to confirm, because match uniqueness ≠ identity, and title is never asserted by policy. (Claimer-side, the analogous name_matches rule requires both first and last name to match, with nickname/spelling tolerance.)
