# Priority Question Answer

Question:
Does the registry-based fix bypass the CMS's stripping of `<style>` and `<script>` tags, and was that security reviewed?

Answer:
No — the registry fix does not bypass the sanitizer; it was designed to respect it. CMS content still passes through the tag-stripping blocklist unchanged — no <style> or <script> ever enters the content field; the content carries only inert, sanitizer-safe placeholder markup, and the executable code lives in dev-authored, dev-deployed global assets that the registry mounts onto those placeholders (Rohit's CSS is likewise handed to devs for global deployment, never inlined). The XSS trust boundary — "CMS authors cannot inject executable code" — is therefore preserved; what the approach works around is only the styling/interactivity limitation, not the security control. A formal security review has not been done — the XSS rationale was explicitly considered in the design discussion, but the standing recommendation is a one-time dev/security sign-off confirming two invariants: the registry mounts only a fixed allowlist of components, and no CMS-supplied string is ever evaluated or rendered as raw HTML by them.
