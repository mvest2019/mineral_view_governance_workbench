# Priority Question Answer

Question:
Does the new GTM purchase tag send any customer PII, such as email or name, into GA4?

Answer:
No — by design the purchase payload contains no PII: the handoff spec's complete field list is transaction_id (order ID), value, currency, and one item with item_id (plan slug like mineral_owner_pro_yearly), item_name (plan name), item_category (account type), item_variant (billing cycle), price, quantity — plan and order metadata only, no email, name, phone, or address anywhere. Two guardrails ensure it stays that way: the spec explicitly tells dev not to use the member ID as transaction_id (stated for dedup reasons, but it also keeps a customer pseudo-identifier out of GA4), and the mandatory GTM Preview + GA4 DebugView verification before the container publishes is where the actually-wired variables get inspected — the one thing to check there is that dev didn't map an email/name variable into any field. GA4's own terms prohibit PII collection, so this check is a compliance gate, not just hygiene, and the payload as specified passes it.
