Question:
Are the zero `spendingtime` values and 98% self-repeating click events a tracking defect, and who owns fixing them?

Answer:
Yes, both are genuine tracking defects in the site's own instrumentation, not analysis errors: the spendingtime/endtime write path has never populated reliably (dwell is unusable — averaging the tiny non-zero minority produces absurd figures like 3,167s), and the same-URL rows are the long-documented double-fire/heartbeat bug re-logging the current page (which also silently deflates any entry-rate metric). The dev team owns the fix, since userbehavior is written by site code — but the recorded strategy is that it may not be worth fixing in place: content-level behavior history is planned to come from Microsoft Clarity (deferred) rather than hardening the homegrown table, and this decision rides Krishna's standing rule that instrumentation must be fixed before any behavioral before/after claims. Until either lands, analysts must apply the standing workarounds — never rank by dwell, filter pageurl <> previouspageurl, and dedupe to first-touch — which is exactly how the blog-pruning analysis was run.
